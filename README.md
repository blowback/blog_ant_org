# Hetzner + SES blog — Terraform

Provisions everything for the personal blog stack:

- Hetzner Cloud server (CX22: 2 vCPU / 4 GB) running the Caddy + Ghost +
  Remark42 + MySQL Docker stack, brought up automatically via cloud-init
- Hetzner Cloud firewall — 80/443 open, SSH locked to your IP
- Amazon SES domain identity + Easy DKIM + a send-only SMTP user, with the
  credentials wired straight into Ghost

DNS stays wherever you keep it today — Terraform just tells you which records
to create.

## Prerequisites

- Terraform >= 1.6
- A Hetzner Cloud project + API token (Console → Security → API Tokens)
- AWS credentials with IAM + SES permissions, exported in your shell:
  `export AWS_ACCESS_KEY_ID=... AWS_SECRET_ACCESS_KEY=...`
- An SSH keypair
- A registered domain you can add records to

## Usage

```bash
cp terraform.tfvars.example terraform.tfvars   # edit it
export HCLOUD_TOKEN=...        # or set hcloud_token in tfvars
export AWS_ACCESS_KEY_ID=...   # SES lives in AWS
export AWS_SECRET_ACCESS_KEY=...

terraform init
terraform apply
```

Then follow `terraform output next_steps`. In short:

1. Create the records from `terraform output a_records_to_create` (two A
   records) and `terraform output dkim_cname_records_to_create` (three CNAMEs)
   at your DNS host. Caddy retries ACME on a backoff, so HTTPS comes up by
   itself once the A records resolve — no ordering dance needed.
2. SES starts in sandbox mode. For a personal blog, verifying your own email
   and staying in sandbox is often enough (you mostly get self-notifications).
   To email arbitrary recipients, request production access in the SES console
   for your region.
3. Check the assigned IP (`terraform output server_ipv4`) against the major
   blocklists. If it's listed from a previous tenant, roll a new one:
   `terraform apply -replace=hcloud_server.blog`
4. Wait ~3–5 min for cloud-init, then open `https://<blog_domain>/ghost`.

## Notes / gotchas

- **Secrets**: MySQL/Ghost/Remark42 passwords are generated by Terraform and
  written only to `/opt/blog/.env` on the server (mode 0600). They live in
  Terraform state too — keep your state backend private (remote + encrypted for
  anything beyond a personal box).
- **SMTP creds**: `terraform output -raw smtp_username` / `smtp_password`. The
  password is region-derived, so don't change `aws_region` without re-applying.
- **Port 587, not 25**: Hetzner blocks outbound 25 by default; SES is reached on
  587, which is fine.
- **MySQL**: pinned to 8.0 (8.4+ removed the auth-plugin flag; Ghost 5 handles
  caching_sha2 natively). Buffer pool set to 512M to suit the 4 GB box.
- **Backups**: `docker compose exec mysql mysqldump ...`, plus the
  `ghost_content` volume; Remark42 auto-dumps to its volume.
- **Adding Cloudflare later** is a DNS/proxy change only — no server changes —
  if IP reputation ever becomes a problem.

## Layout

```
versions.tf            providers + version pins
variables.tf           inputs
main.tf                secrets, SSH key, firewall, server
email.tf               SES identity, DKIM, SMTP user
cloud-init.yaml.tftpl  first-boot config (writes the stack, runs it)
outputs.tf             IP, DNS records, SMTP creds, next steps
```
