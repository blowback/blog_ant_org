# Restoring the blog from an S3 backup

This is the data half of recovery. The infrastructure half is `tofu apply` (which
rebuilds the server from config); this restores posts, images, and comments onto it.

## When you'd do this
- After `tofu apply -replace=hcloud_server.blog` (fresh, empty box)
- After data loss/corruption on a running box

## Prerequisites
- The stack is up on the target box (`docker compose ps` shows mysql/ghost/remark42/caddy)
- DNS already repointed to the box's IP if it changed
- You're SSH'd in as root

## Steps

```bash
cd /opt/blog
set -a; . ./.env; set +a        # MYSQL_ROOT_PASSWORD, BACKUP_BUCKET, AWS creds

# 1. Choose a backup and pull it
aws s3 ls "s3://$BACKUP_BUCKET/"
aws s3 cp "s3://$BACKUP_BUCKET/blog-backup-YYYYMMDDTHHMMSSZ.tar" /tmp/restore.tar
mkdir -p /tmp/restore && tar xf /tmp/restore.tar -C /tmp/restore

# 2. Stop the app containers so nothing writes mid-restore (keep mysql up)
docker compose -f /opt/blog/docker-compose.yml stop ghost remark42

# 3. Restore MySQL (dump has DROP/CREATE, so it replaces the fresh schema)
gunzip -c /tmp/restore/ghost-db.sql.gz | \
  docker compose -f /opt/blog/docker-compose.yml exec -T mysql \
  mysql -uroot -p"$MYSQL_ROOT_PASSWORD" ghost

# 4. Restore the content + comments volumes
docker run --rm -v blog_ghost_content:/data -v /tmp/restore:/in alpine \
  sh -c 'rm -rf /data/* && tar xzf /in/ghost-content.tar.gz -C /data'
docker run --rm -v blog_remark42_data:/data -v /tmp/restore:/in alpine \
  sh -c 'rm -rf /data/* && tar xzf /in/remark42-data.tar.gz -C /data'

# 5. Bring the app back
docker compose -f /opt/blog/docker-compose.yml up -d ghost remark42

# 6. Clean up
rm -rf /tmp/restore /tmp/restore.tar
```

## Verify
- Posts and settings present in Ghost admin
- Uploaded images load on posts
- `source-custom` theme is active again (the active-theme choice rode along in the DB)
- Comments present; GitHub login works and you have moderation controls
  (the admin ID still matches because REMARK_SECRET is stable across server replacement)

## Notes
- The theme *files* come from the Docker image, not the backup; the backup only
  restores which theme is *active* (a DB setting).
- The DB/Remark passwords are unchanged across a server `-replace` (they're
  generated by random_password, which isn't replaced), so the restored dump and
  the new box's .env agree.
- If you ever `-replace` the random_password resources, REMARK_SECRET changes,
  every Remark42 user ID rehashes, and you must reset ADMIN_SHARED_ID.
